# hl-trader 第一步：Hyperliquid 测试网命令行工具

> 日期：2026-10-14
> 状态：历史设计方案；对应功能已实施。当前命令与行为以 [README](../README.md) 和代码为准，原始方案与验收口径保留如下。

## 1. 本步目标与边界

交付一个可独立运行的 Rust CLI，完成“查行情 → 显式提交测试网限价单 → 查订单真实状态 → 按 ID 撤单”的最小闭环。

首版拟仅支持 Hyperliquid 测试网标准 BTC 永续合约和一个独立测试账户。选择该范围是为了验证接口，不是交易或杠杆建议；不支持现货、xyz/HIP-3、子账户、vault 或统一账户模式。如需不同市场，应先调整本方案。

不包含策略、自动循环、AI 决策、Web 后台、数据库、研究系统联动、主网交易、资金划转、提现、授权管理或自动修改杠杆/保证金模式。测试网签名交易也属于写操作，不能因“是测试网”就自动执行。

## 2. 来源与实现方式

- NOFX 参考版本：`622c6f4a16b7904cad7c86ae9bdb84bb7a42bf73`。只参考接入能力及问题清单，不复制或逐行改写其源码、测试、注释和数据库结构。
- 语言与 SDK 选型（2026-10-14 核实）：Hyperliquid 官方仅维护 [Python SDK](https://github.com/hyperliquid-dex/hyperliquid-python-sdk)，无官方 Go/Rust SDK。经用户拍板，本工具改用 **Rust** 实现，签名与协议层复用官方文档收录的社区 Rust SDK [infinitefield/hypersdk](https://github.com/infinitefield/hypersdk)（许可证 MPL-2.0，作为依赖使用可接受，但需在第三方许可记录中注明；MPL 文件级 copyleft 不影响本工具其他代码）。该 SDK 以 alloy 完成 EIP-712 签名、以 rust_decimal 做高精度十进制计算，与本方案“不用二进制浮点计算订单金额”的要求一致；要求 Rust 1.85+。已核实 `hypercore::testnet()`、`Cloid`、`OidOrCloid`（按 oid 或 cloid 撤单）存在；`TimeInForce::Alo` 与按 cloid 查订单状态（orderStatusByCloid）在实现第一步以真实文档和 SDK 源码再次核实，不满足则先报告。
- 依据 Hyperliquid 官方协议文档独立实现 CLI、参数校验、响应解析及测试；不自行设计签名算法。
- 开始实现时固定 hypersdk 及其他依赖版本（提交 `Cargo.lock`）并记录第三方许可。不直接沿用 NOFX 的 `go.mod` 或其任何代码。若依赖许可或功能不满足，先报告，不擅自切换语言或复制 NOFX 实现。
- 参考某项目不等于自动继承其许可，但独立实现也不能仅凭改名获得保证；保留实现来源记录。新项目自身许可证另行确认，不在本步默认指定 MIT 或 AGPL。

## 3. 用户可用命令（拟定）

| 命令 | 作用 | 是否需要私钥 |
|---|---|---|
| `hl-trader market --coin BTC` | 展示测试网价格、数量/价格精度和查询时间 | 否 |
| `hl-trader account --address <address>` | 查询实际交易账户的持仓和挂单 | 否 |
| `hl-trader order --coin BTC --side buy --price <price> --size <size> --cloid <id>` | 默认只预览校验后的限价单；加 `--execute` 才签名提交 | 仅执行时需要 |
| `hl-trader status --address <address> --cloid <id>` | 按客户端订单 ID 查询实际结果，支持超时后人工核对 | 否 |
| `hl-trader cancel --coin BTC --oid <id>` | 默认只预览；加 `--execute` 才撤销指定订单 | 仅执行时需要 |

第一步订单使用 ALO（post-only）限价单，避免下单时立即吃单；挂单之后仍可能成交，不能保证一定可撤销。用户必须显式给出方向、价格和数量，工具不根据余额或模型自动决定。

## 4. 必须具备的安全与正确性约束

### 网络、凭据与权限

- 只允许官方测试网端点 `https://api.hyperliquid-testnet.xyz`；拒绝主网配置，不开放任意 URL 覆盖，也不跟随重定向到其他主机。
- 默认 dry-run：不加载私钥、不生成签名、不发送写请求。下单和撤单均需显式 `--execute`。
- 仅使用单独测试网 agent 私钥。主钱包授权由用户在可信设备完成，CLI 不接收助记词，不提供主钱包签名操作。
- 公共账户地址与 agent 签名地址分开配置；查询使用实际交易账户地址，不使用 agent 地址。发现签名地址与账户地址相同则拒绝，说明这是误用检测，不能单凭地址不同证明授权有效。
- 私钥从用户指定的仓库外秘密文件读取；校验文件所有者和仅所有者可读写的权限，拒绝符号链接。不得通过命令行参数传入、打印到日志或写入结果文件。
- 不读取 `stock_data`、NOFX 的 `.env` 或现有凭据；不开放监听端口。独立仓库不等于同机安全隔离，本步不接入实盘密钥。

### 订单与异常

- 价格、数量按十进制定点处理，不用二进制浮点计算订单金额。通过测试网元数据验证资产与精度；缺少元数据、非法精度、零/负值或超出配置的单笔名义金额上限时直接拒绝，不静默截断或猜默认值。
- `cloid` 是必填的合法客户端订单 ID。执行前将账户、订单意图和 cloid 原子写入本地回执文件；文件权限 0600、运行目录不进 Git。回执不包含私钥、签名或可重放的请求正文。
- 已记录的相同 cloid 不自动再次提交；多进程争用时最多允许一个创建同一意图记录。此机制不能替代交易所状态核对。
- 单进程串行签名与发送，保证 nonce 唯一；本步禁止多个写进程共享同一 agent。进程启动及每次签名前核对时间，禁止自动重试写请求。
- 解析 HTTP 状态、顶层结果与逐订单业务状态。HTTP 200 或顶层 `ok` 不等于成交；真实 ID、已成交数量和价格只能来自实际响应/查询，禁止虚构 `FILLED` 或 `orderId=0`。
- 超时、连接中断、未知响应格式归为“结果未知”，输出 cloid 和查询方法，保留回执，返回非零退出码；不得当作失败后直接再下一单。
- 只撤指定订单，不在开仓前批量撤单，不自动平仓。撤单失败、订单已成交或状态暂不可查询时明确报告，不声称已经消除敞口。
- 明确区分网络失败、无权限、订单拒绝、结果未知与正常空持仓。输出带网络、账户地址、时间与可追踪 ID，不泄露秘密。

金额上限等本地限制用于防误操作；agent 私钥若被盗，攻击者可绕过本工具直接交易，不能把这些限制宣传为账户级资金保护。

## 5. 最小交付与现有项目关系

- Cargo 单二进制 crate：`src/main.rs`（CLI 入口，clap 解析）；`src/hyperliquid.rs`（协议适配）；`src/config.rs`（配置与秘密加载）；`src/receipt.rs`（本地订单意图/回执）。
- 随实现交付 README、无秘密的配置示例、忽略规则、依赖许可记录及离线测试。无需 Web 框架、策略引擎或数据库迁移。
- 不依赖 `stock_data` 的代码、行情库、用户会话或研究目录；不修改 NOFX 和股票项目，不重启现有服务，不开放端口，也不在本步创建远端仓库或发布服务。

## 6. 验收与授权边界

先完成离线验收：构建、单元测试、竞态检查通过；使用 mock HTTP 测试服务器覆盖正常挂单/成交/拒绝、业务错误但 HTTP 200、超时、未知格式、撤单竞态、重复 cloid、精度错误、错误网络、缺失或不安全秘密文件。普通测试不访问主网/测试网，不需要任何真实私钥。

审核方案仅授权后续实现，不代表授权交易。实现完成后，需用户另外明确授权测试网联调并在可信设备准备测试 agent、账户与测试资金；再验证一笔挂单的查询与指定撤销。若期间成交，应如实记录持仓，不自动新增反向订单平仓。未具备条件时标记“离线验收完成、测试网联调未验收”，不能声称交易闭环已通过。

本步验收不代表允许实盘，也不证明已有完整风控、容灾或全天候自动执行能力。完成后停止，不自动扩展下一阶段。

# Hyperliquid 调仓盘口轮询与成交滑点实施合同

日期：2026-11-10。

## 1. 本轮范围

本轮只增加调仓弹窗的只读盘口展示和成交滑点展示：

- 弹窗打开且页面可见时，每 5 秒读取两腿 BBO；关闭弹窗或开始签名/执行后停止轮询。
- 调仓结果和交易历史显示成交均价、相对预览中间价的滑点百分比及滑点金额。
- 保持现有顺序执行、逐腿签名、IOC 保护价和失败后停止后续写入的语义，不改成批量下单。
- 本轮不把弹窗轮询与逐腿发送前刷新 BBO 混为一谈；后者及浏览器逐腿重签仍属独立变更。

实时价格只用于展示和提示旧预览过期，不自动修改已预览、已签名或已落盘的订单。

## 2. 只读盘口契约

新增 Web 入口：

```text
GET /api/v1/hyperliquid/pairs/{pair_id}/adjustment-quote?config_revision=<sha256>
```

后端校验当前 pair 和 revision，调用固定参数的 Rust `adjust-quote --json` 子命令。该命令只读取受控 pair JSON 和官方 `/info` BBO，不加载私钥、不获取写锁、不读取调仓回执，也不发送写请求。

返回 `{data: ...}`，其中数据字段为：

```text
schema_version = 1
pair_id
network
config_revision
queried_at
legs = [
  { coin, bid, ask, mid, book_time },
  { coin, bid, ask, mid, book_time }
]
```

价格使用十进制字符串。缺失、非法或非正价格、配置变化、进程失败均返回错误，不补 0、不返回伪造盘口。

后端按 pair＋revision 做 1 秒成功结果缓存和同 key 单飞，最多两个盘口子进程并发；失败不缓存。页面 API 仍只返回后端结果，不让浏览器直接访问交易所。

## 3. 弹窗状态与过期预览

弹窗独立展示两腿 bid/ask/mid 和盘口时间。轮询失败显示错误；已有旧数据时必须保留其原始时间，不能改写成当前时间。

当最新成功盘口与预览 `mid_px` 不同时：

- 显示“盘口已变化，请重新预览”。
- 禁用托管执行和浏览器签名按钮。
- 用户显式点击重新预览后才生成新报告；托管模式同时生成新的 `request_id`。
- 不用轮询结果覆盖当前报告、确认金额或签名状态。

盘口接口失败本身不伪造过期结论；已有有效预览仍按原安全流程处理。

## 4. 成交滑点口径

后端在确认成交后按已成交数量和预览 `mid_px` 计算，新增可空十进制字段：

- `slippage_pct`：百分比数值，例如 `0.25` 表示 0.25%。
- `slippage_usd`：按成交数量计算的滑点金额。

正值表示不利滑点，负值表示有利滑点：

```text
买入 slippage_pct = (avg_px - mid_px) / mid_px × 100
卖出 slippage_pct = (mid_px - avg_px) / mid_px × 100

买入 slippage_usd = confirmed_qty × (avg_px - mid_px)
卖出 slippage_usd = confirmed_qty × (mid_px - avg_px)
```

部分成交只按已成交部分计算；未成交或缺少有效均价时为 `null`，不补 0。历史报告没有这些字段时前端显示 `—`。

弹窗和交易历史继续分别展示预览中间价、IOC 保护价和实际成交均价，不能混用三者。

## 5. 验证

至少覆盖：

- Rust 盘口 JSON 的身份、精度、配置变化和只读边界。
- 买卖及部分成交的正负滑点；零成交不产生滑点。
- 后端缓存、单飞、失败不缓存、非法响应和 revision 变化。
- 弹窗仅在打开且空闲时轮询，关闭/执行时停止。
- 价格变化使预览过期并禁用执行，重新预览后恢复。
- 弹窗与交易历史的成交均价和滑点展示。
- Rust、Python 离线/临时 PostgreSQL、前端 unit/build 和 Chromium E2E 标准回归。

真实部署、重启及真实下单仍需单独明确授权；离线 mock 通过不代表 IOC 必定成交。

# Hyperliquid 阈值再平衡（第一版后续规划）

日期：2026-11-11。

状态（2026-11-12 更新）：第一版“监控、候选预览、人工确认”已在当前代码实现，尚未部署或进行真实订单验收；不授权真实交易或自动下单。实现包含 migration `012`、指定腿调仓、连续两次确认、候选预览、300 秒默认冷却及结果回写。空仓不生成新开仓候选。Pair 止盈止损与风险退出另见 [HYPERLIQUID_PAIR_RISK_AUTOMATION.md](HYPERLIQUID_PAIR_RISK_AUTOMATION.md)。

## 1. 第一版目标与边界

阈值再平衡用于在持仓偏离目标后恢复目标仓位，不负责预测涨跌，也不是新的开仓信号。第一版只支持：

- 每个 `pair + account` 分别设置两腿固定的目标 USD 名义和偏离阈值，不设置全局限额或统一默认阈值。
- 后端 worker 进行只读监控；达到条件后生成调仓预览并提醒用户。
- 用户核对最新仓位、盘口和订单后人工确认执行；第一版不做全自动下单。
- 复用现有目标仓位调整的减仓优先、reduce-only、IOC 保护价、执行锁和逐腿回执。

暂不支持移动目标、按账户权益自动调整目标、比价偏离交易信号、分批再平衡或自动追单。

## 2. 偏离计算与触发条件

每腿目标名义必须大于 `0`，仓位使用绝对名义计算：

```text
drift_i = abs(abs(current_notional_i) - target_notional_i) / target_notional_i
```

任一腿的 `drift_i` 达到该 pair + 账户配置的阈值，即满足一次候选条件。例如目标为 `2000 USD`、当前为 `2300 USD` 时，偏离为 `15%`；若阈值为 `10%`，该腿进入再平衡候选。

固定目标模式意味着：即使两腿同步从 `2000 USD` 增长到 `2300 USD`，两腿也都会产生 `15%` 偏离，需要分别回到 `2000 USD`。这与只检查两腿是否等名义的模式不同。

第一版要求连续两次检查结果都超过阈值，避免单次瞬时价格波动直接产生预览。两次检查必须使用新鲜的同 pair、同账户、同配置版本数据；中间出现数据缺失、账户切换或规则修改时重新计数。

## 3. 预览与订单生成

达到持续确认条件后，系统生成“回到固定目标”的预览，并记录触发时的两腿仓位、价格、目标、偏离和配置版本。

- 每腿独立判断是否需要订单；未超过阈值的腿保持不动。
- 超过阈值的腿仍需满足交易所最小下单名义和数量精度；不满足时不生成该腿订单，并显示原因。
- 预览不是订单，不会读取私钥或发送写请求。
- 用户确认前重新读取两腿实际仓位、挂单和盘口；前提变化后必须重新预览。
- 已有反向持仓、未处理挂单或同 pair + 账户的其他执行动作时，不生成可执行确认。

示例：NBIS 目标 `2000 USD`、当前 `2300 USD`，CRWV 目标 `2000 USD`、当前 `1980 USD`，阈值为 `10%`。NBIS 偏离 `15%`，生成减仓约 `300 USD` 的预览；CRWV 偏离 `1%`，保持不动。

## 4. 监控、冷却与互斥

自动化监控必须由后端持久 worker 运行，不能依赖浏览器保持打开。worker 停止或数据过期时，页面必须明确显示监控不可用，不能使用旧读数继续判断。

每个 `pair + account` 的状态彼此隔离，至少记录：

- 是否启用监控、两腿目标名义和偏离阈值。
- 最近检查时间、连续超阈值次数和当前偏离。
- 最近候选、预览、用户确认和调仓动作 ID。
- 冷却截止时间和最近执行结果。

一次调仓全部完成后进入冷却期，冷却期间不重复生成候选。发生拒单、部分成交、超时或结果未知时，沿用现有调仓异常处理：保存已确认结果，先核对原订单和实际仓位，禁止冷却结束后盲目重试或反向补偿。

风险退出优先于再平衡。止盈止损触发后必须停止该 pair + 账户的再平衡候选和确认，不能在平仓过程中重新增加某一腿。人工调仓和再平衡确认共用同一执行锁。

## 5. 页面与记录

后续页面至少应提供：

- 当前规则、监控状态和两腿实时偏离。
- 达到阈值的原因、连续确认状态和冷却状态。
- 调仓预览入口，以及确认前的最新盘口和仓位核对。
- 历史候选、人工确认、每腿订单、成交结果和最终仓位。

未启用、worker 停止、数据不足和未达到阈值必须是可区分的状态，不能统一显示为“正常”。

## 6. 离线验收重点

- 偏离公式、绝对名义、目标方向和阈值边界正确；两腿同步偏离也能分别触发。
- 只有连续两次有效检查才生成候选，数据过期或身份变化会重置确认。
- 未超阈值腿不下单，最小名义和精度不满足时明确拒绝该腿。
- 同 pair + 账户的人工调仓、风险退出和再平衡不能并发写入。
- 冷却不重复提醒；部分成交、超时和结果未知不会被当作成功，也不会自动追单。
- 第一版所有真实执行都需要用户人工确认；测试使用 fixture、mock 和临时数据库，不访问真实账户或发送订单。

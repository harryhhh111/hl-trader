# 信息监控推进记录

## 分工与当前交付

交易接口、签名、开平仓联调由 Kimi 推进。信息层位于 `src/intel.rs` 和 `src/intel/announcements.rs`，复用现有只读接口，不改变交易配置或状态。公告页 HTML 使用固定版本 scraper 解析，依赖及许可记录在 [THIRD_PARTY.md](../../THIRD_PARTY.md)。

本轮已实现：

- 独立查询并发执行；行情失败不隐藏已获取的账户资金费收付。
- 非正标记价格不显示为零名义仓位；非正预言机价格不用于资金费预估。
- HYPE/BTC 30MA 必须使用截至昨日 UTC 的连续 30 个共同收盘日；缺日、过期、非法价格明确不可用。
- 比价注明收盘日期，避免将日收盘值当成实时比价。
- 解锁配置检查日期、来源 URL、核实日期；无效条目明确提示，实际申领始终单独标注未核实。
- 公告获取失败只说明本次未取得更新，不推断没有新公告。
- 两腿费率分别展示；新增过去 48 小时账户 pair 资金费净收付，保留最近 3 笔明细。
- 解锁展示未来 7 天全部锚点（含当天、去重），并保留人工来源和实际申领未核实的提示。
- 官方公告和 API 公告并发读取公开 Telegram 预览；校验频道、消息链接、发布时间，去重排序后每个频道展示最近 3 条。响应有大小限制、超时且不跟随重定向；旧公告、无效条目及抓取失败分别标注。

本轮交付按需只读看板。实际申领的自动核验、完整公告历史、后台巡检与推送仍不在本轮范围内。

## 信息源与接入顺序

| 优先级 | 内容 | 当前状态 | 下一步验收条件 |
|---|---|---|---|
| 1 | 官方公告、协议及 API 变更 | 已实现公开频道预览读取，替换候选 RSS 探测 | 页面结构或访问策略变化时降级提示；后续如需完整历史，再接入稳定授权接口 |
| 2 | HYPE 解锁与实际申领 | 人工日历；未接入申领证据 | 日历预告、正式公告、已发生的链上事件分开；金额与日期必须有对应证据，不把转账直接解释为出售 |
| 3 | 市场观察 | 资金费、日线比价和账户信息均来自测试网 | 测试网只用于功能联调；实际市场观察需单独明确公开只读数据的网络，不能与测试账户仓位混算 |
| 4 | 定时提醒 | 未实现，现有方案明确无 daemon | 先确定频率、阈值和通知渠道；持久去重、状态变化提醒、失败恢复提醒；无变化保持安静 |

- [官方支持页](https://hyperliquid.gitbook.io/hyperliquid-docs/support)列出的账号为 [HyperliquidX](https://x.com/HyperliquidX)、[HyperFND](https://x.com/HyperFND)，公告频道为 [hyperliquid_announcements](https://t.me/hyperliquid_announcements)。这些链接确认来源身份，不证明当前运行环境能够自动抓取内容。
- [官方 API 支持页](https://hyperliquid.gitbook.io/hyperliquid-docs/support/faq/building-on-hyperliquid/i-have-api-related-questions)列出 [hyperliquid_api](https://t.me/hyperliquid_api) 作为 API 公告渠道。
- 已移除未经确认的 RSS 候选探测，改用以上两个已核实身份的公开频道；公开预览不等同于完整历史 API。

## 测试边界

信息层回归覆盖行情失败但资金费记录存在、非正价格、日线缺日/过期/未收盘、多条及无效解锁配置、公告来源和时间校验、去重排序、HTTP 错误/重定向/错误类型/响应过大。默认测试使用固定数据和本机 mock，不连接交易所或公告网站、不读真实密钥。

手动公开来源检查为 ignored 测试：`cargo test intel::announcements::tests::public_sources_smoke -- --ignored --nocapture`，只读取公告网站，不加载交易配置。

2026-10-16 实测：官方公告预览成功，能够读取原文链接与发布时间；API 频道预览返回 HTTP 302，按不可用处理并显示原频道入口，未跟随重定向。不能声称两个频道均已实时接通。

公告抓取的可用性、真实解锁信息与线上市场数据仍需分别验收；离线测试通过不能替代这些检查。
